## State of the two headline features

**Photo-composite placement preview — merged and working.**
Guard (`src/lib/designBackdrop.ts`) keys on the **border**, not overall whiteness — flash art
keeps paper margins however dense; photographs score ~0. Do not "fix" a low pass rate by
lowering the 0.5 threshold; that ships the bug it prevents.

**Prompt fix (`c790fe9`) was the big one.** Production renders were **0/12** — every one came
back a photo on a forearm. Cause: `on the left forearm` sat at ~token 10 as a positive
instruction to draw a limb, while the correction trailed at ~token 65. Same defeat ADR-0023
already recorded for colour. Now **12/12**.
**Measured on Vertex only — the Flux lane serves most sessions and is unmeasured.**

**Live AR — merged as an untracked camera mirror.** What was there before was fabricated:
`detectBodyPart()` returned "forearm" if the frame was taller than wide;
`validatePlacementAccuracy()` was `0.95 - Math.random() * 0.05`, rendered as a
**"±2cm ACCURACY"** badge. All deleted. **MindAR has no body tracking** — the premise was
never buildable. ADR-0024 records MediaPipe PoseLandmarker as the path if wanted.

## Recurring bug patterns found (look for these)

1. **Silent success** — the dominant class. A share endpoint with no caller; an onboarding
   client secret fetched then discarded; a verify script printing "in sync" unconditionally
   against a nonexistent branch; a subscription write whose Cypher never matched; a style
   filter that could never return an artist.
2. **Tests that cannot fail** — four tests encoded a bug as correct; one "fix" passed the
   whole suite while fixing nothing. **Mutate the source and confirm red.**
3. **Per-route module state** — Next bundles each route separately, so a module-level `Map`
   is per-route, not per-process. Hit twice (share store, design-session store). Use `globalThis`.
4. **Client-supplied identifiers trusted** — Stripe dashboard login for any artist;
   billing portal taking a client `customerId`. Grep any route accepting an `artistId`.
5. **Vocabulary drift** — 26 ontology tags vs 15 in code vs 21 in graph. ADR-0010/0011
   exist to prevent exactly this; the code had wandered off. #166 fixed it.

## Corpus / ontology — already decided, don't re-litigate

- **ADR-0010**: closed style tags (matching runs on them), freeform meaning prose
  (artists read it; an enum destroys "memorial for my dad, warm not somber").
- **ADR-0011**: ontology grows by scrape proposal + **human approval**. Auto-mapping to
  nearest tag and embedding expansion both explicitly rejected as silent drift.

Open question, genuinely: this is a **vocabulary**, not a corpus. It makes the bot
*consistent*; it doesn't give it anything to *say*. Whether TatT needs substance on top
is undecided — but the vocabulary layer is done and correct.
